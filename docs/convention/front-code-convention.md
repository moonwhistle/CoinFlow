# Coinflow Frontend Code Convention

이 문서는 Coinflow 프로젝트의 프론트엔드 개발 시 준수해야 할 코드 컨벤션을 정의합니다.
CodeRabbit AI 및 동료 리뷰어는 이 규칙을 기반으로 코드 리뷰를 진행합니다.

--------------------------------------------------

1. Naming Conventions (명명 규칙)

1.1 기본 원칙
- 의도 우선: 축약어를 지양하고, 역할과 의미가 드러나는 이름을 사용합니다.
- 일관성 유지: 컴포넌트, 훅, 상수의 네이밍 규칙을 명확히 구분합니다.

--------------------------------------------------

1.2 컴포넌트 (Component)
- PascalCase 사용
- 파일명과 컴포넌트명은 반드시 일치해야 합니다.
- 하나의 파일에는 하나의 컴포넌트만 정의합니다.

예시:
UserProfile.tsx
OrderHistoryCard.tsx

--------------------------------------------------

1.3 Hooks
- 반드시 use 접두사를 사용합니다.
- 관리 대상이 명확히 드러나는 이름을 사용합니다.

예시:
useAuth()
useOrderQuery()
useInfiniteScroll()

잘못된 예:
useData
useLogic

--------------------------------------------------

1.4 변수 및 함수
- lowerCamelCase 사용
- boolean 값은 의미가 분명하도록 네이밍합니다.

예시:
isLoggedIn
hasNextPage
shouldShowModal

--------------------------------------------------

1.5 상수 (Constants)
- UPPER_SNAKE_CASE 사용
- 의미 단위로 묶어서 정의합니다.

예시:
MAX_RETRY_COUNT
DEFAULT_PAGE_SIZE

--------------------------------------------------

2. Architecture & Structure (구조)

2.1 디렉토리 구조 (권장)

frontend/
src/
components/     재사용 가능한 UI 컴포넌트
pages/          라우트 단위 컴포넌트
hooks/          Custom Hooks
services/       API 호출 로직
stores/         상태 관리
utils/          순수 유틸 함수
types/          전역 타입 정의
constants/      전역 상수

컴포넌트 기준이 아닌 책임 기준으로 분리하는 것을 원칙으로 합니다.

--------------------------------------------------

2.2 컴포넌트 책임 분리

Presentational Component
- UI 표현만 담당
- props 기반으로 동작

Container / Page
- 데이터 조회
- 상태 관리
- 이벤트 핸들링

하나의 컴포넌트에서 API 호출, 상태 관리, UI 렌더링을 모두 처리하지 않습니다.

--------------------------------------------------

3. State & Side Effects

3.1 상태 관리 기준
- 로컬 상태: useState
- 서버 상태: React Query 또는 SWR
- 전역 상태: 정말 필요한 경우에만 사용

--------------------------------------------------

3.2 Side Effect 관리
- useEffect 사용은 최소화합니다.
- 의존성 배열은 정확히 명시합니다.
- eslint-disable 남발을 금지합니다.

--------------------------------------------------

4. TypeScript 규칙

4.1 타입 안정성
- any 사용을 금지합니다.
- 공용 인터페이스 및 도메인 타입은 명시적으로 선언합니다.

예시:
interface User {
id: number;
name: string;
}

--------------------------------------------------

4.2 Props 타입 정의
- Props 타입은 반드시 분리하여 정의합니다.
- 재사용 가능하면 types 디렉토리로 이동합니다.

예시:
interface UserCardProps {
user: User;
onClick: () => void;
}

--------------------------------------------------

5. Coding Style & Clean Code

5.1 함수 설계
- 하나의 함수는 하나의 역할만 수행합니다.
- 조건 분기 깊이를 최소화합니다.
- Early Return 패턴을 적극 활용합니다.

--------------------------------------------------

5.2 렌더링 로직
- JSX 내부에 복잡한 조건문을 작성하지 않습니다.
- 렌더링에 필요한 값은 사전에 계산합니다.

--------------------------------------------------

6. Error Handling
- API 에러는 공통 레이어에서 처리합니다.
- 컴포넌트 내부에서 try-catch 남발을 금지합니다.
- 사용자 메시지와 로그는 분리합니다.

--------------------------------------------------

7. Testing (권장)
- React Testing Library 사용을 권장합니다.
- 테스트는 구현이 아닌 행동을 검증해야 합니다.

예시:
로그인 버튼 클릭 시 로그인 요청을 보낸다
