# #65 [FEAT] Late Tick 실시간 재계산 및 차트 보정 구현

## 📌 Summary
수집 지연이나 네트워크 문제로 **뒤늦게 도착한 체결 데이터(Late Tick)** 때문에 이미 차트에서 마감된 과거 캔들의 데이터(종가, 고가/저가, 거래량 등)가 누락되거나 맞지 않는 고질적인 문제를 해결했습니다.
기존 아키텍처를 뒤엎지 않고, In-Memory 기반의 실시간 재계산 및 프론트엔드의 과거 차트 보정 기능(Hot Path)을 전체 데이터 흐름에 매끄럽게 추가 및 적용 완료했습니다.

## 📚 Changes
클래스 단위가 아닌 **데이터가 흘러가는 핵심 흐름(Flow) 중심**으로 개선된 사항은 다음과 같습니다.

1. **[Core] 실시간 지연 틱을 담아두는 '최근 마감 버퍼(RecentlyClosedBuffer)' 도입**
   - 현재 진행 중인 라이브 캔들이 아니더라도, 최대 120초(2분) 이내에 닫힌 캔들이라면 메모리 상의 임시 버퍼에 안전하게 보관하도록 파이프라인 구간을 연장했습니다.
2. **[Flow] 과거 시간대 데이터의 실시간 재연산 로직 생성**
   - 틱 데이터가 도착했을 때 해당 틱이 "이미 지난 시간대"의 정보라면, 일반 로직을 타는 대신 버퍼에서 마감됐던 캔들을 다시 꺼내옵니다.
   - 꺼낸 캔들에 이 늦은 틱 정보를 섞어서 High(고가), Low(저가), Close(종가), Volume(거래량)을 다시 계산해 온전한 과거 캔들 데이터로 소생시킵니다.
3. **[Broadcast] 프론트엔드 차트 붕괴를 막는 브로드캐스팅 순서 보장**
   - 소생된 과거 캔들 정보(`lateUpdatedSnapshots`)는 진행 중인 최신 캔들이나 일반적인 마감 캔들보다 **무조건 먼저 프론트엔드 및 Redis로 브로드캐스트**됩니다. (프론트엔드 차트의 오래된 데이터 업데이트 거부 에러를 방지)
4. **[DB] 완전한 덮어쓰기로 단일 진실 공급원(SSOT) 준수**
   - 기존의 DB 구조는 데이터가 오면 기존 값과 합치는 식(`merge`)이었으나, 이를 전부 제거하고 메모리 애그리게이터가 보내준 최종 완성본 캔들을 DB에 그대로 **덮어쓰기(`apply`)** 하도록 구조를 뜯어고쳤습니다. 이로써 메모리와 DB가 영구적으로 동일한 상태를 유지합니다.
5. **[Frontend] 과거 캔들 리렌더링 개방**
   - 프론트엔드 차트 라이브러리(Lightweight Charts)의 `update()` 함수 옵션 중 `historicalUpdate: true`를 활성화했습니다. 이제 백엔드에서 늦게 도착한 과거 캔들을 보내주면, 차트가 에러 없이 스르륵 꿀렁이며 과거 캔들을 보정해서 다시 그립니다.

## 📝 Note
### 🚨 사전 검토(Critical Review) 취약점 해결 적용 현황
진행 전 계획 수립 과정에서 발견된 **치명적인 동시성(Concurrency) 취약점**이 성공적으로 해결되어 반영되었습니다.

* **발견되었던 문제:**
  초당 수백~수천 개의 틱이 다양한 스레드를 통해 쏟아지고 백엔드 집계기(`KlineAggregator`)에 접근하는데, 지연 틱을 담아두는 버퍼를 일반 자료구조(`LinkedHashMap`)로 설계할 경우 `ConcurrentModificationException`이 발생하며 백엔드 셧다운이 발생할 위험이 컸습니다.
* **적용된 개선안:**
  버퍼 코드를 단순히 선언하지 않고, `Collections.synchronizedMap()`으로 한 꺼풀 감싸도록 설계/구현했습니다. 이렇게 함으로써 다중 틱 삽입/조회가 동시에 일어나도 완벽하게 **Thread-Safe**가 보장되는 환경을 구축했습니다.

### 🛠️ 프론트엔드 연동 및 시뮬레이션 시각 테스트 완료
Late Tick이 발생할 때 프론트엔드 UI가 충돌 없이 부드럽게 과거 캔들을 다시 그리는지 검증하기 위하여 별도의 시뮬레이션을 진행했습니다.

- **방법:** `simulate_late_tick.sh` 쉘 스크립트를 작성하여 로컬 Redis Stream(`tick:raw`) 환경에 의도적으로 **80초 전(이전 마감된 캔들 시간대)**의 이벤트 타임과 이질적으로 높은 가격(`150,000`)의 틱 데이터를 1건 단독 주입했습니다.
- **결과:** 프론트엔드 차트의 1분봉에서 아무런 오류를 뱉지 않고 **지나간 이전 캔들의 위쪽 꼬리가 즉각적으로 치솟는 애니메이션(꿀렁임)**을 즉시 확인 완료했습니다. Hot Path의 양단 연결(백엔드 버퍼 ~ 프론트엔드 리렌더링) 무결성을 증명했습니다.
